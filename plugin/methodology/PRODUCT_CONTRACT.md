# 제품 목적과 기본 실행 계약

이 문서는 개발 지침·실행 스킬·제품 인수 시험이 함께 따르는 사용자 성과 기준이다. 특정 시점의 병목 후보·점수·기업 순위를 정답으로 정하지 않는다. 현재 구현 상태는 이 문서와 별도로 관리한다.

## 사용자가 이 플러그인을 설치하는 이유

**AI 인프라 공급망의 어디가 막히는지, 얼마나 심각한지, 어떻게 변하고 있는지를 파악하고 이해하기 쉽게 지속적으로 확인하기 위해서다.**

- 위치: 어떤 공급망 구간·제품/규격·지역·프로젝트에서 제약이 발생하는지 찾는다.
- 심화도: 수요 대비 가용 공급의 부족, 지속성, 실제 구축/가동 영향을 구분해 판단한다.
- 추세: 비교 가능한 과거와 현재에서 심화·완화·새 제약을 추적하고 판단 변경 근거를 보존한다.
- 전달: 사용자가 핵심 요약·공급망 비교·변경 내역에서 결과를 이해하고 원문 근거와 다음 관측으로 이어갈 수 있게 한다.

스킬·보고서·대시보드·객체 지도·API·SQLite는 이 성과를 구현하는 수단이다. 기업 공시와 재무 정보는 공급망 질문에 필요한 근거로 사용한다. 산업경제성·기업 투자분석은 요청된 경우의 후속 계층이며 핵심 병목 조사 과제를 대신하지 않는다.

## 기본 동작

“연구를 시작해줘”, “AI 인프라 병목 현황을 보여줘”처럼 별도 대상을 지정하지 않은 최초 연구는 **공급망 범위 탐색 → 중요한 후보의 심층 검토 → 분야 간 종합**으로 시작한다. 임의의 회사 질문이나 종목을 사용자에게 만들게 하지 않는다. 기존 프로젝트의 범위·기준일을 우선하며 신규 연구에서는 AI 인프라 공급망을 기본 대상으로, 실행일을 기준일로 명시한다. 비교·전망 기간과 미검토 범위도 드러낸다. 제품 목적이 이미 정해져 있다는 이유로 사용자 연구의 결론이나 점수를 미리 정하지 않는다.

광역 탐색에서 원출처와 미검토 영역을 확인한 뒤 운영 영향·중요 변화·가설과 반증에 따라 깊이 조사할 대상을 선정한다. API가 편리한 미국 기업이나 이미 유명한 후보로 연구 범위를 제한하지 않는다. 고정 후보 수·확정 순위를 채우지 않는다. 조사 자료는 질문별로 저장·재조회하고 분야별 판단을 종합하여 맥락 손실을 줄인다.

사용자가 특정 구간/질문을 지정하면 그 범위를 우선한다. 설명·요약만 요청하면 저장된 상태부터 답하고 전체 신규 연구를 시작하지 않는다. 업데이트는 기존 판단→새 근거→유지/변경 이유→다음 관측으로 이어가며 보고서를 처음부터 반복 작성하지 않는다.

SEC·IR·공개 정형자료·웹의 역할은 질문이 정한다. 가격 수집은 물리 병목 판단의 필수 통과 조건이 아니다. 필요한 설정이 없는 경로는 실패/미설정을 기록하고 독립적으로 가능한 조사를 계속한다. 어떤 adapter의 성공도 병목 판단이나 실제 심층 리서치 성공을 자동 증명하지 않는다.

## 연구 결과와 제품 인수

최초 종합 결과에는 핵심 요약, 공급망 위치별 비교, 주요 후보의 근거·반증·이력, 변화 판단, 다음 추적 항목과 원문 색인이 있어야 한다. 강도·지속성·영향·확신도·범위 제한은 요약에서도 유지한다. 숫자 평가가 불가능하면 가능한 정성 판단과 미식별 부분을 구분한다. 표를 만들었다는 이유로 비교 불가능한 scope에 글로벌 순위를 붙이지 않는다.

제품 인수는 사용자가 위치·심화도·추세를 이해하고 근거를 확인하며 다음 실행에서 같은 판단을 이어갈 수 있는지 평가한다. 기술 POC의 소수 자료·저장/HTTP/테스트 성공과 구분한다. 대표 제품 시험은 최초 탐색·심층 판단·종합 전달·갱신을 연결해야 하며, 특정 기업 자료 취득만으로 대체하지 않는다. 시험의 고정 날짜/범위는 일반 사용자의 영구 기본값이 아니다.

변경을 설계할 때에는 이 네 성과 중 무엇을 개선하는지, 어떤 실제 사용자 과제로 확인할지, 현재 구현의 어느 부분이 아직 부족한지 기록한다. 기존 구현이 계약을 충족하지 못하면 구현 공백으로 남기며 문서만 수정하고 기능 완료로 처리하지 않는다. 자동 검사·작성자 검토·독립 해석 검토·사용자 인수·배포는 별개다.


최초 연구의 실행·재개·중간 결과와 검토본 구분은 [연구 실행 계약](../workflows/RESEARCH_EXECUTION.md)을 따른다. API는 기존 조사량과 깊이를 늘리는 수단이며 자료 취득 실패 뒤 조사 축소의 이유가 아니다. 스킬 직접 수행과 별도 도구 수행을 구분한다. 처음 저장한 날짜 이전의 공개 이력을 복원하고, 해결 가능한 핵심 공백에는 후속 조사를 이어간다.


첫 실행 전수 조사 계약(2026-09-14 사용자 결정): 기존 87개 노드 모두 실제 자료 탐색·검토를 수행한다. 모든 노드에 수요/공급·과거 이력·반증·가동 영향·추세 질문과 조사 결과 또는 조사 후 공백을 기록한다. 조사 이후의 Unknown/Missing은 허용하지만 미조사 노드를 제외해서 완료하는 것은 금지한다. 추가 심층 대상 선정은 전수 조사를 대체하지 않는다. 모든 노드의 채점이나 같은 자료 수를 요구하는 규칙은 아니다.
