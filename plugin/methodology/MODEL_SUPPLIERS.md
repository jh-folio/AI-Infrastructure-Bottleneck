# F01 · AI 모델 개발·공급사

사용자 요청으로 추가한 **하나의 조사 노드**다. 기업별로 별도 Node_ID를 만들지 않는다. 모델을 직접 개발하고 API·관리형 서비스·모델 가중치로 공급하는 기업군을 대상으로 한다. 자체 모델이 없는 앱/단순 재판매 사업자는 이 노드의 공급사로 세지 않는다. 클라우드 사업자는 자체 모델 개발·공급 역할과 타사 모델 유통·인프라 제공 역할을 구분한다. 이름만으로 공급망 역할이나 독립성을 확정하지 않는다.

## 무엇을 판단할 것인가

| 기존 질문 차원 | 이 노드에서 확인할 내용 |
|---|---|
| 수요·가용 공급 | 학습·추론을 구분한 수요와 실제 사용 가능한 공급. 모델/API의 공개 범위, 가용성·용량 제한·가격·서비스 조건 변화와 그 원인. 발표된 투자액·파트너 계약을 실제 가동 용량으로 대체하지 않음 |
| 과거 이력 | 이전 모델/제품 공급 계획→실제 출시·지역 확대·용량 확보·지연의 이력. 발표일·서비스 가능일·측정 기간을 구분 |
| 대안·반증 | 다른 공급사/모델, 공개 가중치·자체 호스팅, 소형화·증류·캐시·추론 효율 개선으로 수요가 달라지는지. 가격 하락이나 벤치마크 향상만으로 인프라 부족 해소를 단정하지 않음 |
| 가동 영향 | 모델 공급 제한이 고객의 실제 도입·처리량·서비스 운영에 미치는 영향과 공급사가 요구하는 연산/데이터센터 용량. 지역·모델·배포 방식·기간을 명시 |
| 추세 | 동일 조건의 공급 접근성·가격/성능·처리량/지연·효율·인프라 확보 변화. 모델 세대나 벤치마크 조건이 다른 값을 그대로 연결하지 않음 |

가능한 자료는 모델·API 공식 문서와 출시/변경 기록, 서비스 상태·용량 안내, 모델 카드/기술 보고서, 상장사의 공시·실적 자료, 인프라 공급자·고객의 독립적인 확인 자료다. API 키를 구매하거나 모델 API에 추론 요청을 실행하는 조사가 아니다. 기술 성능/활용 발표와 실제 수요·가동 관측을 구분한다. 비공개 기업의 매출·학습 비용·사용량은 출처가 확인된 주장/외부 추정으로 표시하고 없으면 Unknown으로 둔다. 홍보·재인용 기사는 원출처와 계보를 확인한다.

## 하나의 노드에서 기업 차이를 보존

F01 아래 기업/모델군/지역/배포 방식/학습·추론/기간별 판단 범위를 나눌 수 있다. 기업별 근거와 반증은 해당 범위에 귀속하고, 기업 수만큼 새 노드를 생성하거나 전체 공급망 수준의 결론을 복사하지 않는다. 주요 공급사의 역할·공급/접근 변화·인프라 확보·대체 가능성을 비교하되 자료 수나 기업 수의 고정 할당량은 만들지 않는다. 전체 시장을 다뤘는지, 일부 공급사만 확인했는지를 밝힌다. 같은 공시/제품 문서를 재사용하고 노드별 가용 원문만 인계한다.

모델 공급사는 인프라 수요의 발생 지점이자 모델 공급의 주체다. 모델 출시 일정·품질 격차·가격·수익성·기업가치와 물리적 인프라 병목은 별도 판단이다. 파라미터 수·벤치마크·시장점유율·기업 가치만으로 v3.1 점수를 채우지 않는다. 기존 factor 정의에 맞는 범위/근거가 있을 때만 점수를 계산하고 그 외에는 정성 판단·미평가를 유지한다. 개별 증권의 투자 매력도는 별도 투자 계층에서 판단한다.

## 목록·지도·기존 연구

F01은 원래87개 ID를 보존한 추가 정의 `node_extensions_v1.json`에 있다. 새 목록 model-providers-v1은88개, 기본 investment-supply-v1 조사 대상은78개/맥락10개다. 전수 조사에는 F01의 다섯 질문 차원이 포함된다. `model_supply` 분야에 한 노드로 배정한다. A01 연산장치·B02 랙 통합→F01의 기본 선은 재검토 전 참고 의존이며 공급 부족이나 관측된 지연 전파의 증거가 아니다. 실제 전파는 근거를 검토해 별도로 등록한다.

기존 campaign과 보고서에는 자동 삽입하지 않는다. 새 research-start는 최신 추가 정의를 사용한다. 현재 연구에 추가해달라는 명시적 요청이 있으면 최신 checkpoint에서 기존 node-change(add)로 F01의 ID/이름/범위·추가 사유·유효일을 기록하고 조사한다. 같은 ID가 이미 다른 의미로 쓰였으면 덮어쓰지 말고 충돌을 보고한다. 기존 증거·점수·관계는 자동 이관하지 않는다. 신규 시작에 catalog_version=legacy-id-map-1.0을 명시하면 원래 목록을 재현할 수 있으나 기본값은 최신 목록이다.
