# d5.12 실제 계정 효율·품질 재시험

이 문서는 시험 절차다. 로컬 회귀 통과는 Work/Cowork 사용량·조사 품질 인수가 아니다. 테스트는 기존 연구 원본을 백업한 별도 프로젝트에서 수행한다. 버전은 `0.3.0-d5.12`(Work ZIP은 `0.3.0-d5.12-work.1`)인지 확인한다.

## 동일 조건

- 이전 시험과 같은 모델·추론 수준·기준일·질문 범위를 사용한다. 새 기본 범위는 78개이며 기존 campaign은 자동 축소하지 않는다. 현재 scope_profile의 포함 ID를 비교한다.
- 최초 조사, 중단 후 재개, 변경 자료가 있는 업데이트를 구분한다. 전수 탐색·노드별 판단·반증·공백 재조사·최종 종합 기준은 유지한다.
- 원문 파일·DB·usage_metrics.jsonl과 최종 결과를 보존한다. 계정이 표시하는 실제 사용량만 별도 기록하고, 제공하지 않는 토큰/모델 턴/압축 횟수는 미관측으로 남긴다. 호출/문자량을 실제 토큰 절감률로 바꾸지 않는다.

## 실행 확인

1. 실제 호스트의 병렬 지원 여부로 coordination을 설정한다. 지원 시 동시 수 2부터 시작하고, 미지원이면 순차 처리한다. `research-dispatch`가 제안한 claim을 주 에이전트가 실행하고 실제 담당자를 연결한다. 명령 자체가 에이전트나 예약을 생성한 것으로 보고하지 않는다.
2. 현재 checkpoint에서 `impact-scan`을 한 번 호출해 비교 기준을 저장한다. 최초 scan은 이전 변경을 추정하지 않는다. 기존 자료 재검토가 목적이면 explicit document_ids/record_ids 또는 explore=true를 사용한다. 최초 연구의 미해결 질문은 항상 기존 대기열에 남는다.
3. 공유 원문을 읽고 작은 `research-work-unit`을 편성한다. 실제 보유한 구간만 known_segments로 전달한다. 표 머리·단위·주석·부정·관측/계획 구분을 확인하고, 질문별 적용과 판단을 따로 기록한다. 배정된 작업은 submit/apply 경로를 지킨다.
4. 실제 검토한 닫힌 질문에만 review-seal을 만들고, 재개 시 review-status/use를 확인한다. 다른 작업 진행만으로 모든 원문을 다시 읽지 않는지, 원문 정정/새 반증/재검토 기한에는 다시 읽는지 확인한다. 작성자와 coordinator 및 최종 종합 검토를 합치지 않는다.
5. 자료 취득·monitor-run 뒤 안정된 최신 checkpoint로 새 impact-scan을 실행한다. `impact-details`의 모든 페이지에서 변경 자료→질문/보고서 경로를 확인한다. 영향 미분류 자료·실패는 검토 대상으로 남아야 한다. 무관한 질문에 같은 설명을 복제하지 않는다.
6. 변경 대기열은 research-dispatch→기존 coordination으로 계속 처리한다. 실행 중단 뒤 같은 DB를 재개했을 때 처리한 기록과 미해결 변경이 보존되어야 한다. claim의 중복/동시 수 제한과 실제 호스트 대기·예약을 확인한다. 완료 뒤 예약 중단은 실제 호스트 응답으로 검증한다.
7. 기본 30일의 탐색 주기(운영상 설정, 채점 기준 아님)가 도래하거나 explore=true이면 현재 포함 범위의 질문이 다시 조사 대상으로 열리는지 확인한다. 새 노드/대체 경로 탐색을 변경 자료만으로 대체하지 않는다.
8. Cowork은 연결된 폴더의 내구 사본을 사용하고 새 세션에서 discover/restore 결과와 해시를 확인한다. 로컬 복구 성공만으로 실제 호스트 연결을 통과 처리하지 않는다.

## 제출할 최소 자료와 판정

보고서·dashboard.html·research.sqlite·usage_metrics.jsonl·실행 요약을 제출한다. 공유 전 개인 경로/연락처/원문 재배포 가능 여부를 확인한다. 요약에는 설치 버전, 모델·추론 수준, 실제 실행 시간, 현재 포함/조사/미조사 노드 수, 실패·재개, 호스트 사용량 제공 여부를 적는다.

품질은 노드별 고유 출처·원문 적용·반증·가동 영향·추세·분야 간 종합으로 판단한다. 78행 생성, 테스트 통과, 긴 실행 시간만으로 성공 처리하지 않는다. 화면은 같은 검증 snapshot을 사용하고 대시보드·공급망 지도 두 화면의 가독성과 상세 열기를 별도 확인한다.
