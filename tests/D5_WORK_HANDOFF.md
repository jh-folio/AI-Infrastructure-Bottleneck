# D3–D5 통합 Work 점검 — 0.3.0-d5.1

목표는 AI 인프라 공급망 병목의 위치·심화도·추세를 알기 쉽게 설명하고 지속 추적하는 것이다. 기존 D1 DB와 사용자 연구를 보존한다. 설치 폴더·상태 폴더는 실제 확인한 위치를 사용하며 임의로 초기화하지 않는다.

## 1. 버전과 상태 발견

manifest 0.3.0-d5.1과 runtime/UI 파일을 확인하고 기존 project_id로 audit한다. 이전 보고서와 snapshot을 찾는다. 로컬 테스트 성공은 실제 Work 실행 증거와 구분한다. 신규 프로젝트가 필요한 경우 기존 폴더를 덮어쓰지 않는다.

## 2. 심층 리서치 연결과 정정 보고서

기존 공급망 질문과 검토 자료를 research-handoff로 고정한다. 실제 환경의 심층 리서치 스킬/도구를 발견해 지침에 따라 호출한다. 실행 기록과 반환 결과가 있으면 research-return으로 각각 등록한다. 기능이 없거나 확인할 수 없으면 상태와 이유를 그대로 기록하고 가능한 원문 검토를 계속한다. 일반 웹 조사나 코드 렌더링을 심층 리서치 수행으로 기록하지 않는다.

이전 보고서에서 발전원 접속→데이터센터 부하 인입 전용, 전망→관측, 증설→수요 충족, 미검토 반도체 구간을 넘는 비교를 재검토한다. 실제로 입증되는 범위로 정정하고 기록을 연결한다. runtime guide의 judgment_reviews·research_execution·comparison_scope를 포함해 새 synthesize를 수행한다. 새 결과도 원문으로 검토한 뒤 채택한다.

## 3. 반복 수집과 갱신

등록된 SEC/IR/가격 중 필요한 경로를 monitor-plan으로 저장한다. monitor-run에 실제 회차 기준일과 고유 request_id를 주고 실행한다. 같은 회차 재시도는 같은 ID를 사용한다. 실패/부분 취득을 변화 없음과 구분하고, 바뀐 원문만 검토하여 필요한 근거·판단·보고서를 새 이력으로 연결한다. 성공·실패·검토 필요를 실제 실행 기록에서 확인한다.

실패로 끝난 회차를 재수집하려면 새 request_id를 사용한다. 날짜 범위가 필요한 가격 자료는 계획의 start/end가 실제 조사 기간인지 확인한다. 자동으로 현재 날짜를 미래 실적으로 바꾸지 않는다. 예약은 사용자가 요청한 주기·시간대가 있을 때 호스트 도구로 별도 등록한다. schedule-packet 생성만으로 예약 활성화를 주장하지 않는다.

## 4. 보고서와 동일한 지도·화면

지도에 필요한 관계를 relation으로 기록한다. from_judgment_id는 출발 구간, to_judgment_id는 의존하거나 영향을 받는 구간이다. 기술적 의존은 실제 지연 전파가 아니며, 관측/조건부 전파는 원문·기간·두 대상 연결 근거를 설명한다. 관계를 기록한 뒤 생성한 보고서만 그 관계를 포함한다. 과거 보고서에 새로운 관계를 몰래 추가하지 않는다.

export-dashboard로 해당 report_id의 단일 HTML을 새 파일에 생성하고 Work에서 연다. 외부 CDN/서버/API 키가 필요 없는 읽기 전용 파일이다. Work가 파일의 스크립트를 실행하지 못하면 HTML 표시 실패를 기록하고 보고서/데이터는 보존한다. 이를 실제 인터랙티브 화면 성공으로 표시하지 않는다.

확인할 행동: 구간 선택→근거/반대 근거→출처, 검색/지역/추세 필터, 지도 전환/관계 필터/확대·이동/구간 선택, 모바일, 변경 요약, 수집 실패 표시. 화면의 snapshot_id가 보고서와 같은지 확인한다. 순서·연결 수·지도 크기를 점수로 해석하지 않는다.

## 5. 재접근과 인수

audit/backup 후 새 Work 실행에서 기존 상태와 보고서·화면을 재접근한다. 직접 확인한 결과와 미검증 항목을 분리해 기록한다. 전달 자료는 자연어 보고서, HTML, 실제 심층 리서치 수행/반환 근거, 반복 수집 실행 기록, 재접근 검증이다. 개인 자료·DB를 배포 저장소에 올리지 않는다.
