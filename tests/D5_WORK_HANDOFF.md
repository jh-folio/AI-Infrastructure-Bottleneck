# 실제 최초 연구 인수 — 0.3.0-d5.6

목표는 AI 공급망의 병목 위치·심화도·추세를 이해할 수 있는 실제 결과다. 짧은 패키지 smoke test가 아니다. 버전과 기존 상태 경로를 먼저 확인하되 단위 테스트 반복·ZIP 생성에 연구 시간을 소모하지 않는다. 기존 D1/D3 데이터는 보존하고 없는 DB를 재생성해 기존 상태라고 하지 않는다.

1. plugin/workflows/RESEARCH_EXECUTION.md와 build-baseline 스킬을 적용한다. 기존 자료를 재조회하고 research-start 또는 research-resume으로 전반 탐색→심층 검토→종합을 이어간다. 과거 계획/실현을 복원하고 수요·공급·미충족·반증·가동 영향·변화를 비교한다. 수집 경로 실패 뒤에는 대체 자료를 조사한다.
2. 실제 심층 리서치 스킬을 직접 수행한다. 별도 실행 도구가 없어도 스킬 절차는 수행할 수 있다. 실제 도구가 있는 경우에만 해당 호출을 이용한다. 수행 경로/자료 조회/공백 재조사/주요 해석 변경 기록과 결과를 별도 파일로 남긴다. 사용하지 않은 기능을 사용했다고 기록하지 않는다.
3. source_reviews에 실제 원문 위치·인용·알아낸 내용·범위 적합성을 연결하고 질문 묶음마다 checkpoint한다. research-next의 남은 조사를 같은 실행에서 계속한다. 중간 저장은 내부 작업이며 최초 요청을 중간 기준선으로 축소해 종료하지 않는다. 시간·자료 수·파일 생성은 종료 조건이 아니다. 실제 호스트 중단·도구 제한·사용자 중지로 계속할 수 없을 때만 미완료 기록을 인계한다. 이번에는 여러 실행 분할·예약을 도입하지 않는다.
4. 종료 기준을 검토한 뒤 baseline_review로 자연어 보고서를 생성한다. 무엇이 어디서 막히며 어느 범위에서 심각하고 어떻게 달라지는지, 어떤 근거가 결론을 바꾸는지 설명한다. 자료 수/채점 수를 채우기 위해 근거를 창작하지 않는다. 현재 구현은 구조적 종료 조건을 검사하며 의미 판단은 작성자가 책임진다.
5. 동일 snapshot으로 대시보드·지도를 내보내고 실제 열기·조작·모바일을 확인한다. 표시 차단은 연구 부족과 분리해서 기록한다. 등록 관계만 표시하며 미평가를 점수로 채우지 않는다.
6. research-completion에 최신 campaign_id/report_id를 전달하여 제출 조건을 확인한다. false면 이유를 해결하며 같은 실행에서 계속한다. 검토본과 audit/backup, 노드별 출처 검토 원장, 실제 심층 리서치 수행/결과 기록, 완료 확인 JSON을 함께 인계한다. 새 Work 대화 재접근과 여러 실행 분할은 이번 검증 범위가 아니다. 개인 원문/DB를 배포 저장소에 올리지 않는다.

반복 수집/예약/중복 방지 등 기술 회귀는 별도 개발 테스트다. 이번 사용자 연구에서 해당 기술 시험을 완료하기 위해 조사 범위를 축소하지 않는다. 반복 실행 기능은 RUNTIME_GUIDE의 D4 명령을 따른다.


첫 실행 전수 조사 계약(2026-09-14 사용자 결정): 기존 87개 노드 모두 실제 자료 탐색·검토를 수행한다. 모든 노드에 수요/공급·과거 이력·반증·가동 영향·추세 질문과 조사 결과 또는 조사 후 공백을 기록한다. 조사 이후의 Unknown/Missing은 허용하지만 미조사 노드를 제외해서 완료하는 것은 금지한다. 추가 심층 대상 선정은 전수 조사를 대체하지 않는다. 모든 노드의 채점이나 같은 자료 수를 요구하는 규칙은 아니다.


노드 변경이 필요한 실제 근거가 있으면 node-change로 추가/분할/통합하고 최신 연구 대기열에 반영되는지 확인한다. 기능을 시험하기 위해 실제 연구에 임의 노드를 만들지 않는다. 원본87개와 이전 판단·계보는 보존하고 새 유효 노드 모두 조사한다.
