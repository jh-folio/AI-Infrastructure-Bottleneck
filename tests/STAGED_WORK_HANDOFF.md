# 분야별 병렬·자동 재개 Work 인수 시험

대상 후보: 0.3.0-d5.9. 기존 D1/D5 DB는 보존하고 별도 시험 연구를 사용한다. 이 시험은 전체87개 연구의 완료 선언이 아니다. [자동 조사 계약](../plugin/workflows/AUTOMATIC_RESEARCH.md)을 따른다.

## 실제 실행 요청

> 설치 버전이 0.3.0-d5.9인지 확인하고 tests/STAGED_WORK_HANDOFF.md에 따라 병렬 조사와 자동 재개를 시험해줘. 별도 연구에서 반도체 A01–A11과 전력장비·계통 C01–C09를 조사해줘. 실제 지원되는 하위 에이전트로 두 분야를 나누고, 원문 검토 뒤 공통 DB에 반영해줘. 같은 연구 대화에 후속 실행을 예약해서 내가 새 메시지를 보내지 않아도 저장한 질문에서 이어지는지 확인해줘. 시험 범위가 끝나면 중간 보고서와 대시보드/지도, 실행 증거와 백업을 남기고 예약을 중단해줘. 나머지67개는 미조사로 유지하고 전체 조사 완료라고 표시하지 마. 기존 연구는 수정하지 마.

자동 진행의 회차·실패 한도와 예약 주기는 실제 호스트 지원 및 사용자가 정한 범위로 설정한다. 이 요청은 제한된 시험의 자동 진행 요청이며 무기한 정기 모니터링 요청이 아니다. 모델/추론 수준은 사용자가 선택한 설정을 유지한다.

## 확인할 결과

1. 두 분야의 실제 위임 ID/범위·작업 시각·분리된 원문/검토 산출물을 기록한다. 단순 Python 동시 요청을 에이전트 병렬 조사로 세지 않는다.
2. 주 에이전트는 개별 원문·적용 범위·시점·반증을 검토한 후 순차 반영한다. 원문의 소개/색인에서 후속 문서를 실제로 읽고, 근거 부족은 노드별로 검토한 공백이어야 한다. 반복 문장이나 일반 메모리→HBM 전용을 허용하지 않는다.
3. 실제 예약 도구의 예약 ID와 등록 결과를 저장한다. schedule-packet 파일만 생성한 것은 실패다. 다음 실행이 사용자 메시지 없이 시작됐다는 호스트 실행 ID/시각을 남기고 현재 project/campaign/checkpoint 및 원문 해시를 대조한다. 오래된 업로드로 새 DB를 생성하면 실패다.
4. 후속 실행에서 남은 질문을 실제 조사하고 추가 근거/검토를 저장한다. 상태 조회만으로 자동 조사 재개 성공이라고 하지 않는다. 진행 중인 작업을 중복 배정하지 않으며 중단·재시도 후 이력을 보존한다.
5. 두 분야의 질문과 원문 의미 검토가 끝나면 interim 보고서·동일 snapshot HTML·원문 목록·노드별 원장을 생성한다. full campaign의 research-completion은 나머지 미조사 때문에 false여야 한다. 소규모 시험 종료는 coordination-control paused로 기록하고 실제 호스트 예약을 중단한 뒤 coordination-schedule stopped 영수증을 저장한다. coordination-finish로 전체 완료를 위조하지 않는다.
6. 예약 중단 후 실행이 도착해도 새 조사를 하지 않는지 확인한다. 지원 기능·최신 상태 복원·자료 접근에 막히면 정확히 미검증/실패로 기록한다. 수동 재개 성공을 자동 재개 성공으로 바꾸지 않는다.

사용자에게는 조사 품질 요약, 보고서/HTML, 실행 검토와 재개 가능한 백업을 전달한다. 내부 JSON 수십 개를 사용자가 직접 이어 붙이게 하지 않는다. 성공 판정은 원문 검토·병렬 조율·무인 재개·저장 보존·독자 화면을 따로 적는다.


## d5.11 사용량 비교와 범위 확인

패키지 버전0.3.0-d5.11을 확인한다. 기존 연구는 당시 범위로 재개하며 초기화를 하지 않는다. 새 연구에서는 research-resume.scope_profile이 기본78/맥락10인지 확인한다. 기존 연구의 범위를 바꾸려면 명시적 요청 뒤 research-scope를 사용한다.

A01–A11/C01–C09에서 공통 문서·반증·역사·인허가 지연 경쟁 설명을 포함하는 작은 표본으로 시작한다. 동일 모델/추론·기준일·범위에서 가능한 동일 원문을 사용해 기존 방식과 비교한다. 원래 연구를 비용 비교만을 위해 전체 재실행하지 않는다. 고정 자료 재생과 실제 검색의 변동을 구분한다.

research-resume/coordination-packet의 compact 응답, research-question-update, 필요한 source-context.known_segments, research-batch를 사용한다. 진행 중 usage-summary를 저장하고 호스트가 실제 토큰/사용량을 제공하면 별도 증거를 보관한다. CLI 문자/바이트 측정을 실제 토큰으로 표시하지 않는다. 관측된 제한으로 끊기면 새 project/campaign을 만들지 말고 같은 checkpoint의 다음 행동으로 재개한다. 지원되지 않는 자동 예약을 선언하지 않는다.

확인 항목: 이전 원문/질문/시도 보존, 동일 항목 중복 등록 없음, 범위 밖10개를 기본 종결 의무로 다시 만들지 않음, 중요한 인허가/인력 원인은 포함 노드의 미해결 질문으로 유지, 기본 지도78개와 범위 설명, 과거87개 보고서 유지. 표본의 원문 적합성·반증·역사·주요 결론은 이전과 같거나 더 충실해야 한다. 비용 감소만으로 조사 완료라고 판정하지 않는다. 표본 통과 후20개로 확대하며 새 기본 범위에서20개 외58개는 미조사다(기존 full-catalog 연구에서는67개).

사용자에게 전달할 자료는 usage-summary 결과, 호스트 사용량 증거(제공되는 경우), 비교 범위/품질 검토 요약과 재개 가능한 백업이다. 실제 총사용량 절감률과 한도 내 완료는 이번 실행에서 관측된 결과만 보고한다.

F01 AI 모델 개발·공급사는 한 노드인지, 새 연구 기본78개에 포함되고 model_supply 분야에서 다섯 차원으로 조사되는지 확인한다. 기업별로 별도 노드를 생성하지 않는다. 기본 참고 연결을 관측된 지연 전파로 표시하지 않는다. 기존 연구는 자동으로 노드가 늘어나지 않으며, 요청 시 node-change(add)로 명시적으로 편입한다.
