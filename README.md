# AI Infrastructure Bottleneck

AI 인프라 공급망의 **어디가 막히는지, 얼마나 심각한지, 어떻게 변하는지** 조사하고 보고서·대시보드·공급망 지도로 확인하는 개인 연구 플러그인입니다. 연구 자료와 이력은 사용자별 프로젝트에 보관합니다.

현재는 사용자 워크플로우 검증용 Preview입니다. 실제 계정 설치·Work 연구 품질·장기 저장·예약 인수는 별도입니다. 설치 버전은 플러그인 상세 또는 “설치 버전을 확인해줘”로 확인하세요.

## ChatGPT Work 개인 설치 방법

GitHub 플러그인 설치를 사용할 수 없는 개인 환경에서는 [통합 스킬 ZIP 다운로드](https://github.com/jh-folio/AI-Infrastructure-Bottleneck/releases/download/v0.3.0-d5.9-work.1/ai-infrastructure-bottleneck-work-0.3.0-d5.9-work.1.zip)를 사용하세요.

1. ZIP을 다운로드하고 ChatGPT Skills 관리 화면에서 계정에 제공된 가져오기/업로드 기능으로 등록합니다. 압축 해제를 요구하면 안의 `ai-infrastructure-bottleneck` 폴더를 사용합니다. 일반 대화 첨부만으로 설치 완료로 판단하지 않습니다.
2. 새 Work 작업에서 `ai-infrastructure-bottleneck`을 선택하거나 “AI Bottleneck으로 무엇을 할 수 있는지 알려줘”라고 요청합니다.
3. “AI Bottleneck으로 처음 시작해줘”라고 요청하면 설정부터 조사·검토·보고서와 화면까지 연결합니다. 기존 연구는 “이어서 조사해줘”로 재개합니다.

ZIP에는 통합 SKILL.md와 다섯 내부 INSTRUCTIONS.md, 공통 연구 코드가 포함됩니다. 자세한 설치·업데이트·백업 안내는 ZIP 안의 README.md에 있습니다. 업데이트 전 연구 상태를 백업하고 새 ZIP 적용 후 같은 프로젝트에 재접근하세요. 플러그인 전용 upgrade 명령은 Work판에서 지원하지 않습니다.

Python·SQLite 실행과 자료 검색이 필요합니다. 실제 개인 계정 설치·장기 저장·호스트 병렬·예약/자동 재개는 미검증이며 계정의 지원 기능을 확인해야 합니다. 기존 플러그인 설치 방식은 아래 안내를 따릅니다.

## 설치하고 시작하기

1. 배포자가 제공한 설치 링크나 계정의 공유 플러그인 목록에서 **AI Bottleneck**을 엽니다. 현재 배포 출처는 [GitHub 저장소](https://github.com/jh-folio/AI-Infrastructure-Bottleneck)이며 비공개로 운영되는 경우 저장소 접근 권한이 필요합니다. 공개 디렉터리에 등록된 제품이라고 가정하지 마세요.
2. 해당 환경이 제공하는 설치 버튼으로 설치하고 활성화합니다. GitHub 링크 설치 기능이 없는 환경에서는 배포자/관리자에게 계정에서 사용할 설치 링크 또는 가져온 플러그인 목록을 요청하세요. 임의 폴더에 파일을 복사해 설치를 대신할 필요는 없습니다.
3. 새 **Work 대화**를 시작하고 이 플러그인을 선택합니다. 5개 스킬은 함께 포함되므로 하나씩 설치하지 않습니다. 이미 열려 있던 대화에서는 새 스킬이 보이지 않을 수 있습니다.
4. 다음과 같이 요청하세요.

> AI Bottleneck으로 처음 시작해줘. 필요한 설정부터 AI 공급망 조사, 보고서와 지도까지 이어서 진행해줘.

에이전트가 실행 환경과 기존 연구를 확인합니다. 기존 상태는 보존하며 이어가고, 새 연구면 접근 가능한 저장 위치를 정해 시작합니다. 기본 범위는 AI 인프라 공급망이고 기준일은 실행일입니다. 이미 정한 정보를 반복해서 물어보거나 임의의 기업을 먼저 고르도록 요구하지 않습니다.

먼저 기능만 알아보려면 **“이 플러그인으로 무엇을 할 수 있는지 알려줘”**라고 요청하세요. 도움말은 긴 연구를 시작하지 않습니다. 최초 전체 연구는 기존87개와 이후 추가·분할된 유효 노드를 실제로 조사하므로 짧은 기능 점검과 다릅니다.

Codex에서도 제공된 플러그인 목록에서 설치한 뒤 새 작업을 시작합니다. Work Cloud와 로컬 Codex의 파일 접근·저장 위치는 다르며 같은 파일이 자동 공유된다고 가정하지 않습니다. 호스트마다 메뉴·설치 경로가 다를 수 있습니다. [공식 설치 안내](https://learn.chatgpt.com/docs/plugins), [배포 방식 안내](https://developers.openai.com/plugins/build/plugins).

## 원하는 일을 말하면 됩니다

| 하고 싶은 일 | 요청 예시 | 진행 방식 |
|---|---|---|
| 처음 조사 | “처음 시작해줘” | 설정→공급망 탐색→역사·반증 검토→종합→보고서·화면 |
| 질문 보강 | “HBM 공급 제약만 더 조사해줘” | 지정한 질문만 조사하고 근거·불확실성 설명 |
| 중단한 조사 계속 | “이어서 조사해줘” | 저장한 질문·자료·진행 위치부터 재개 |
| 새 자료로 갱신 | “지난 보고서 이후 바뀐 내용을 업데이트해줘” | 기존 판단과 새 근거 비교→변경 요약·결과 갱신 |
| 기존 내용 요약 | “저장된 내용만 짧게 요약해줘” | 새 자료를 수집하지 않고 기존 결과 요약 |
| 판단 이유 확인 | “왜 전력 인입이 병목이라고 판단했어?” | 저장 원문·판단·반증·남은 공백 설명 |
| 보고서와 화면 보기 | “저장된 보고서와 지도를 보여줘” | 해당 보고서와 같은 기준의 화면 표시 |
| 정기 확인 요청 | “매주 월요일에 변화를 확인해줘” | 주기·시간대·저장 경로와 호스트 지원 확인 후 실제 예약 결과 안내 |

설정·조사·검토·출력을 단계마다 별도로 지시할 필요는 없습니다. “분야별로 병렬 조사하고, 완료까지 자동으로 이어가줘”라고 요청하면 지원되는 호스트 기능을 확인해 연결합니다. 실제 병렬·예약 도구와 최신 연구 상태 접근이 필요하며, 이 후보의 Work 무인 재개는 아직 인수 전입니다. 미완료 연구는 중간 저장 뒤에도 같은 실행에서 계속합니다. 호스트 제한이나 사용자 중지로 멈췄다면 완료로 표시하지 않고 재개 위치를 남깁니다. 화면이나 설명만 요청했는데 새 전체 조사를 시작하지 않습니다.

## 결과 읽기와 다시 사용하기

최초 종합 결과는 **보고서와 대시보드/공급망 지도 HTML**로 제공합니다. 대시보드에서 구간을 선택해 판단·원문·관측 이력을 읽고, 지도에서 공급 방향과 관계 근거를 확인하세요. HTML 표시가 제한되면 보고서와 다운로드 가능한 파일을 제공합니다.

기준일·범위·중간/검토 상태를 먼저 확인하세요. 근거 부족은 0점이나 “문제 없음”이 아닙니다. 과거 계획과 실제 관측, 점수 추세와 정성 변화, 기술적 의존과 확인된 지연 전파를 구분합니다. 병목 강도는 투자매력도와 같지 않습니다.

에이전트가 연구 위치와 마지막 진행 기록을 인계 문서에 남깁니다. 다음에는 같은 프로젝트에서 “이어서 조사해줘” 또는 “최신 자료로 갱신해줘”라고 요청하세요. HTML/보고서만으로 모든 원문과 DB가 복구되지는 않습니다. **“현재 연구를 백업해줘”**로 DB 백업도 보관하세요. 다음 세션의 실제 재접근 여부는 해당 환경에서 확인합니다.

## 플러그인 업데이트와 복구

“연구 내용을 갱신해줘”와 “플러그인 버전을 업데이트해줘”는 다른 작업입니다.

> 기존 연구를 보존하면서 플러그인 업데이트를 준비해줘.

에이전트는 신뢰하는 출처의 새 패키지와 기존 데이터의 호환성을 확인하고 별도 백업을 만듭니다. 이후 기존 설치 출처의 갱신 기능으로 업데이트하고 **새 대화**에서 같은 연구를 다시 열어 이전 자료 보존을 확인합니다. 설치 화면에서 사용자 조작이 필요하면 해당 단계만 안내합니다.

미지원 DB 형식이나 검증 실패 시 원본을 보존하고 필요한 조치를 알려줍니다. 업데이트가 기존 점수·기준일·승인 상태를 자동 변경하지 않습니다. 복구는 “이 백업을 새 폴더에 복구해줘”로 요청하며 기존 연구를 덮어쓰지 않습니다. 백업 이후 추가 내용은 복원본에 없을 수 있으므로 두 상태를 함께 보존합니다.

## 막혔을 때

| 증상 | 다음 조치 |
|---|---|
| 플러그인/스킬이 보이지 않음 | 같은 계정의 설치·활성화와 비공개 저장소 권한 확인 후 새 대화 시작 |
| 기존 연구를 찾지 못함 | 이전 인계 문서나 DB 백업 위치 확인. 새 초기화로 덮어쓰지 않음 |
| 프로젝트가 여러 개임 | 이름·기준일로 프로젝트 선택 |
| 저장된 보고서가 없음 | 진행 중이면 “이어서 조사해줘”, 새 연구면 “처음 시작해줘” |
| Python/SQLite 실행 불가 | 지원되는 Work/로컬 실행 환경 확인. 텍스트 답변을 DB 저장 성공으로 표시하지 않음 |
| 일부 원문/PDF/SEC 취득 실패 | 가능한 다른 공식 원문·호스트 도구로 조사 계속 |
| HTML이 열리지 않음 | 보고서 또는 HTML 다운로드로 확인. 인터랙티브 표시 성공과 구분 |
| 예약 기능이 없음 | 수동 갱신 사용. 예약 지시문 파일만으로 예약 완료라고 표시하지 않음 |

무료 공개자료를 조사하지만 호스트 구독·사용량까지 무료라는 의미는 아닙니다. 선택 기능인 SEC 직접 수집에는 식별 연락처 설정이 필요할 수 있으며, 전체 조사의 필수 조건은 아닙니다. 개인 DB·원문·비밀정보를 배포 저장소에 올리지 않습니다.

## 실행자를 위한 참고

일반 사용자는 명령이나 스킬명을 외울 필요가 없습니다. 에이전트가 [사용자 흐름](plugin/workflows/USER_WORKFLOW.md), [명령 안내](plugin/workflows/RUNTIME_GUIDE.md), [자료와 질문 연결](plugin/workflows/SOURCE_QUESTION_FLOW.md), [검토와 제출](plugin/workflows/REVIEW_AND_DELIVERY.md)을 적용합니다.

Python 3.10+와 SQLite를 사용합니다. PDF/가격 수집의 선택 의존성은 `requirements-optional.txt`에 고정되어 있으며 필요한 경로에만 설치하거나 실제 호스트 동등 도구를 사용합니다. 의존성 설치 자체를 연구 실행으로 기록하지 않습니다. Sites 통합 관리 공간은 후속 확장입니다.
