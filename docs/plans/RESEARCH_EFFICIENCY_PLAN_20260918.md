# 조사 비용 절감과 기본 범위 조정 계획 — 2026-09-18

### 9.1 목표·근거·적용 경계

사용자는 d5.9에서 조사량은 늘었지만 초기 조사에 5시간 사용량 한도를 약4회 소진할 정도의 부담을 보고했다. 이는 사용자 관측이며 계정별 토큰 한도나 공통 호스트 정책을 확인한 수치가 아니다. 실제 실행 로그가 없어 비용의 원인별 비중은 미확인이다. 기본 구독 환경에서도 누적 조사 결과를 보존하며 감당할 수 있는 사용량으로 운영하는 것을 제품 품질 목표에 추가한다. 특정 요금제·모델의 한도나 초기 전체 조사를 한 회차에 끝낼 수 있음을 약속하지 않는다.

현재 소스에서 확인한 개선 후보는 research_loop.resume의 전체 nodes/questions 반환, coordination.packet의 담당 노드별 전체 질문 기록 전달, 담당자 원문 검토 뒤 주 에이전트의 원문 확인·수동 등록 절차다. 이미 있는 question/patch, question-packet/source-context, 원문 캐시를 재사용하며 새로운 저장소나 스킬을 늘리지 않는다. 이 구조가 실제 사용량에서 차지한 비중은 별도 측정한다.

이번 요청은 **계획 수립**이다. 아래 범위 변경과 성능 개선은 구현 후 적용하며 현재 ontology·제품 계약·완료 검사·사용자 DB·배포물은 변경하지 않는다. 기존87개 전수 조사와 지도 표시는 기존 계약이고, 새 범위 프로필 구현 후에는 아래의 명시적 포함/제외 계약으로 대체한다. 조사 품질 기준과 v3.1 점수 계산은 유지한다.

### 9.2 조사 범위 제안 — 기본77개와 필요시 확인하는 외부 요인

| 독립 전수 조사에서 제외할 기존 ID | 현재 의미 |
|---|---|
| E01 | 인허가·환경 승인 |
| E02, E03, E04 | 전기공·송전 작업 인력·전기 엔지니어 |
| E05, E06 | 전문 제조/팹 인력·보호/제어 엔지니어 |
| E08, E10, E11, E12 | 용접공·건설 인력·시운전 전문가·전력회사 검토/엔지니어링 인력 |

제안상10개를 독립 기본 조사에서 제외하므로 원래87개 기준 기본 대상은77개다. **E07 EPC Capacity, E09 Water / Environmental Resource Constraints, E13 Powered Land / Siting은 유지**한다. 각각 수행기업의 수주/시공능력, 물의 물리적 가용성, 실제 전력 확보 부지와 연결되므로 직종·규제 전수 조사와 구분한다. EPC 조사에서도 직종별 인력시장 전수 조사로 다시 확장하지 않는다. C 분야의 전력망 접속·전력 공급 노드는 유지한다.

제외는 삭제/미조사 은폐/해결 처리와 다르다. 기본87개 ID·정의·의존관계·기존 근거·점수·보고서를 보존하고, campaign에 포함/제외 ID, 사유, 적용일, scope_profile_version을 기록한다. ontology의 active 상태나 기존 excluded disposition을 편의상 재사용하지 않고 조사 범위와 노드 생존 상태를 분리한다. 신규·분할·통합 노드는 계보와 범위를 검토해 편입하며77을 영구 고정하지 않는다. 기존 campaign은 자동 축소하지 않고 명시적 범위 전환 기록 또는 새 campaign을 통해 적용한다. 과거 완료 상태/보고서는 소급 수정하지 않는다.

범위 밖10개는 기본 질문5개씩을 생성·종결할 의무가 없다. 다만 포함 노드의 공급·증설·가동 일정·대체 경로·추세를 판단하는 데 중요하면 관련 요인으로 조사한다. 구체적 지연 발표, 부족 원인의 경쟁 설명, 계획 실현과의 불일치가 조사 촉발 조건이다. 근거 위치·영향받는 노드·지역/기간·관측/계획 구분·미해결 사항을 남기며 인허가 지연을 설비 부족으로 잘못 채점하지 않는다. 중요 원인 공백은 해당 포함 노드의 질문을 열린 상태로 유지한다.

기본 화면은 대시보드/공급망 지도 두 개를 유지한다. 독립 순위와 기본 지도에는 포함 노드를 표시하고, 제외 요인은 해당 노드 설명에서 지연 원인으로 보여준다. 범위 요약에는 전체 목록87/기본 포함77/범위 밖10을 명시하고 동적 변경도 반영한다. 범위 밖을 미조사·낮은 점수로 표시하지 않는다. 숨긴 노드에 연결된 선을 다른 노드로 자동 우회시키지 않는다. 과거 snapshot은 당시 범위로 재현한다.

### 9.3 비용 절감 설계

1. **측정부터 추가:** CLI별 입력/출력 바이트·문자 수, 작업/문서/질문 ID, 원문 동일 구간 재조회, 전달 기록 크기, 작성/검토/통합 단계와 재개 횟수를 기록한다. 가능한 호스트의 input/output/reasoning/cached 토큰은 제공된 항목만 별도 수집한다. CLI 측정은 호스트의 숨은 프롬프트·추론·도구/대화 문맥 전체를 포괄하지 않으며 문자량을 실제 토큰/요금/5시간 한도로 표시하지 않는다. 원문·연락처·비밀정보는 측정 로그에 복사하지 않는다.
2. **작은 응답을 기본으로:** resume/status는 요약·최신 checkpoint·미완료 개수·다음 행동·페이지 cursor를 기본 반환한다. 전체 원장 export는 파일로 저장하고 경로/크기/해시만 반환한다. 상세 조회와 변경분 patch는 기존 경로를 확장한다. 기존 소비자 호환을 위해 명시적 상세 옵션 또는 버전 구분을 두며 누락된 원장을 완료로 오인하지 않게 한다.
3. **작업 인계 축소:** 담당자에는 맡은 질문의 현재 판단·미해결 행동·필요한 근거 위치만 전달한다. 과거 전체 시도/완료 기록은 요청 시 조회한다. 전달 크기에 맞춰 작업 묶음을 조정하되 남은 항목/cursor를 명시한다. 인계 문서를 만들면서 다른 모델이 다시 요약하는 일을 기본으로 추가하지 않는다. 호스트가 제한된 문맥 위임을 지원하면 사용하고, 지원하지 않으면 전체 대화 상속이 비용에 미치는 영향을 별도로 기록한다.
4. **원문 재사용:** 문서 버전/해시/위치 기준으로 원문과 추출 사실을 한 번 저장하고 여러 질문에서 참조한다. 노드별 관련성·평가 범위·반증 판단은 별도로 유지한다. 관련 구간과 앞뒤 문맥을 우선 전달하며 표 머리·단위·주석을 보존한다. 충분하지 않거나 상충하는 경우 원문 범위를 넓힌다. 읽은 구간 캐시가 최신 확인이나 새로운 질문의 의미 검토를 대신하지 않는다.
5. **모델의 기록 작업을 코드로 이전:** 담당자 산출물의 source/adopt/judgment 참조 연결·중복 검사·저장·검증 응답을 묶음 처리하고 결과 ID 매핑과 실패 항목만 반환한다. 모델은 실제 근거 채택과 적용 판단에 책임을 지며 코드는 판단을 생성하지 않는다. 주 에이전트는 전달 파일 전체를 재서술하지 않고 주요 결론·새로운 주장·상충 근거·오류 징후를 원문으로 검토한다. 모든 주장은 추적 가능해야 하며 미검토 주장을 검토 완료로 표시하지 않는다. 오류 발견 시 관련 범위의 검토를 확대한다. 단일 DB 쓰기·중복 방지·부분 실패 복구를 보존한다.
6. **제한 중단과 재개:** 정확한 잔여 한도를 모르는 상태에서 한도 임박을 추측하지 않는다. 관측 가능한 호스트 제한 또는 사용자가 정한 운영 예산에 따라 checkpoint를 저장하고 미완료로 중단한다. 저장된 다음 행동에서 이어가고 완료된 검색·보고서를 다시 만들지 않는다. 제한 중 실패한 호출을 반복하지 않으며 실제 재개 도구·허용 시각 정보가 있을 때만 예약을 사용한다. 자동 예약 지원이 없으면 재개 상태를 보존하고 제한을 알린다.

병렬은 시간 단축과 총사용량을 구분해 평가한다. 같은 범위의 순차/병렬 표본을 비교하고 동시 수는 별도 실행 설정으로 둔다. 모델/추론 수준 변경, 유료 API·외부 서버 추가, 품질 검사를 완화한 저비용 모드는 기본 해법에 포함하지 않는다. 예산 소진은 연구 완료가 아니다.

### 9.4 구현 순서와 인수

| 단계 | 변경 범위 | 통과 조건 |

P0→P1→P2→P3→P4 순서다. 계획만으로 런타임의 전수 조사 규칙을 바꾸지 않는다. 후속 구현에서 AGENTS·PRODUCT_CONTRACT·RESEARCH_EXECUTION·AUTOMATIC_RESEARCH·5개 스킬·완료 검사·UI·인수 안내의 모순을 함께 제거한다. 점수 방법 버전과 조사 범위 프로필 버전은 별개다.

시험은 A01–A11/C01–C09에서 공통 문서 재사용·반증·역사·중단 복구·인허가에 의한 일정 제약을 포함하는 소규모 표본으로 시작하고20개로 확대한다. 기존 방식과 개선 방식은 같은 모델/추론·기준일·대상·가능한 동일 원문 snapshot을 사용한다. 검색 변동이 있는 실제 실행 비교와 고정 자료 재생 비교를 구분한다. 원본 사용자 DB를 복제해 읽기 검증하고 기존 실행에 불필요한 전체 재조사를 요구하지 않는다.

정량 개발 목표는 **동일 고정 자료·업무 경로에서 플러그인이 반환/인계하는 누적 텍스트를 기존 대비50% 이상 축소**하는 것이다. 실제 총토큰50% 절감 보장이 아니며, 아직 계측하지 않은 목표다. 전체 토큰을 관측할 수 있다면 별도로 전후 수치를 보고하고 캐시/추론 포함 여부를 밝힌다. 10개 범위 제외 효과와 동일 범위 최적화 효과를 따로 측정한다.

품질 인수는 포함 노드의 실제 탐색·5개 질문 차원·역사·반증·범위 적합성·주요 결론/원문 계보가 유지되고, 반복 공백·소개 페이지 종결·일반 메모리→HBM 전용 등의 기존 오류를 다시 허용하지 않는 것이다. 원문이 정당화하는 결론 차이는 설명하고 필수 사실/반증 누락으로 생긴 차이는 실패다. 사용량이 줄어도 품질 기준이 실패하면 완료하지 않는다. 초기 전체 연구를 한 번의5시간 한도에서 마치는 것은 미검증이며 인수 약속으로 두지 않는다.
